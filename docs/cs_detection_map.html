CS Detection

Cloud ML is the hardest layer — it sees global patterns across all CrowdStrike customers. A binary that looks benign locally can be flagged by cloud if its structure matches known malware families.

Gap Analysis

Coverage Gaps

DLL sideloading: 4 sideload recipes exist but none tested against CS. This is the highest-value untested vector — signed parent process inherits trust from Falcon.

CPL format: Control Panel applets (.cpl) executed via control.exe are a less-monitored execution path. Untested.

Memory scanning (TDT): 6 countermeasures exist but none validated against Intel TDT hardware-accelerated scans specifically.

Kernel callbacks: PPID spoofing works but kernel-level callback removal requires BYOVD. No BYOVD chain implemented in the framework.

Key Findings

api_resolve is REQUIRED for all PE formats. Every PE that passes CS uses dynamic API resolution via hash-based lookup. Static imports of sensitive APIs = instant detection.

resources + manifest = ML bypass. The resource section + embedded manifest combination is what passes CrowdStrike's cloud ML. This is the single most important evasion technique.

JScript is the most reliable format. 13/17 total PASS results are JScript. No PE analysis, no import table, no entropy measurement. Limited by COM/WMI capabilities.

19 FAIL_NO_C2 are NOT detection failures. These binaries survived CrowdStrike but the C2 listener had protocol mismatches (HTTP vs TCP) or timing issues. Retesting with correct C2 infrastructure could convert many to PASS.
